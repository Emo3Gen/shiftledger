# Задание для Агента 1 — 2026-04-03

## Задача: SL-001 — Баг противоречий в расписании
**Приоритет:** 🔴 высокий

## Суть проблемы
Движок расписания может назначить сотрудника на смену, на которую тот сказал «не могу». Это происходит в фазе ребаланса минимальных часов.

## Контекст
Файл: `backend/scheduleEngineV0.js`

В движке есть несколько фаз назначения:
1. **Step 1.5** (строки ~143–179): собирает список недоступных (`unavailableBySlot`) — это работает правильно.
2. **Основное назначение** (строки ~390–450): фильтрует недоступных через `safeCandidates` — это тоже работает.
3. **Phase 2.5 — ребаланс** (строки ~456–498): пытается перераспределить смены, чтобы сотрудники с `minHours` набрали нужное количество часов. **Здесь проверки недоступности НЕТ.**

## План действий

### Шаг 1: Диагностика
Прочитай `scheduleEngineV0.js`, фокус на Phase 2.5 (ребаланс, строки 456–498).
Найди цикл:
```
for (const [empId, minHours] of employeesNeedingMore) {
  ...
  for (const slot of availableSlots) {
    ...
    if (!slot.candidates.includes(empId)) continue;
    ...
  }
}
```
Проблема: `slot.candidates` собирается из SHIFT_AVAILABILITY, но **не учитывает** более поздние SHIFT_UNAVAILABILITY. Переменная `unavailableBySlot` уже содержит правильные данные, но в этом цикле не используется.

### Шаг 2: Исправление
Добавь проверку недоступности в цикл ребаланса. Перед назначением проверяй:
```javascript
const unavailForSlot = unavailableBySlot.get(slot.slotKey);
if (unavailForSlot && unavailForSlot.has(empId)) continue;
```

### Шаг 3: Тест
Напиши тест в `backend/__tests__/scheduleEngineV0.test.js`:
- **Сценарий:** u1 доступен на пн утро и вт утро. u4 доступен на пн утро и вт утро. u4 отмечает недоступность на вт утро. После сборки расписания u4 НЕ должен быть назначен на вт утро, даже если у него не хватает часов до минимума.
- **Название:** `rebalance does not assign unavailable user to slot`

### Шаг 4: Прогон всех тестов
Запусти `npm test` и убедись, что все тесты (включая новый) проходят.
